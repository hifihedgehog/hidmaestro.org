# hidmaestro.org design guide

This site is the padforge.org v6 design system, applied to HIDMaestro.
The system's rules, the rationale behind them, and the twelve things not
to do live in `padforge.org/DESIGN.md`, the family spec. Read that file
before adding anything here. The one rule carries over unchanged:

**Show the product. Say less. Prove it elsewhere.**

## The two-surface split

| Surface | Job | Density |
|---|---|---|
| `index.html` | Sell. One idea per viewport. | Sparse. |
| `specs.html` | Prove. Answer everything. | Dense, structured. |
| `/docs/` | Teach. | Whatever the topic needs. |

`specs.html` is generated by `tools/build_specs.py` from
`_features.json`, `_faq.json`, and `_cmp_full.html`. Edit the data or
the generator, then re-run. Hand edits get overwritten. When new detail
arrives it goes to `_features.json` by default, and it earns a place on
the product page only if it changes what the product is.

## What differs from padforge.org

- The product is an SDK, so the code panel (`.code-panel`) is a product
  shot and gets staged like one. It appears once.
- The latency chart stays flat (`.chart-shot`): angling a data chart
  taxes the one thing it exists for.
- The screenshots are 4-up API collages rather than single app windows.
  They still ride the rig, whole and unclipped.
- PadForge-only components (the colorway morph, the annotated
  controller, the device check) are absent here, removed from the
  stylesheet rather than left as dead rules.

## Before you ship

The checklist is padforge.org/DESIGN.md section 11, with this repo's
harness: `python tools/make_capture.py` writes `_capture.html`, which
collapses the 100svh hero and freezes motion so a tall screenshot shows
the real page. Capture it, LOOK at it, and check 780px and 400px.
Edge headless enforces a ~500px minimum window width, so a true 400px
check needs `--force-device-scale-factor=2 --window-size=800,...`.
