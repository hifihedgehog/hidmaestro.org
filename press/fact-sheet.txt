HIDMaestro
Product information | November 19, 2026

HIDMaestro is a free, open-source SDK for creating virtual game controllers, keyboards and mice on Windows. Applications use its C# API and JSON device profiles to define device identity, submit input, and receive output such as rumble and force feedback. PadForge uses HIDMaestro for virtual controller output. HIDMaestro is available under the MIT license, including for commercial use.

Architecture
Applications submit input through the C# SDK. JSON profiles describe device
identity and reports. On x64 the core HID/XUSB paths use Windows UMDF2. Composite USB
profiles, and every profile on ARM64, use a signed usbip-win2 transport for USB
HID, audio and vendor interfaces.
Output events return to the application, which handles physical-device routing.
Input API support depends on the selected profile.
Version 2.0.0 moves device behavior out of code and into the profiles.
Programs built on HIDMaestro 1.x must move to 2.0.0.
Version 2.0.1 removes HIDMaestro from a computer, with HIDMaestroUninstall.exe
from the release ZIP or one call from a program, and installs usbip-win2's
host controller without usbip-win2's installer or its root-hub filter.
Version 2.0.2 gives the Steam Deck and Steam Controller personas the motion,
report timing, unit serials, pad pressure and trigger bits that SDL and Steam
read from the real controllers.
Version 2.0.3 makes a removal that includes usbip-win2 take usbip-win2's
root-hub filter too, which an SDK through 2.0.0 installed.
Version 2.1.0 fixes frames that arrived late, out of order or twice, keeps the
Xbox 360 profiles' HID devices alive across a system sleep, and cuts the work
the SDK, the driver and the USB/IP transport do for each frame.
Version 2.2.0 adds sinput, an SInput gamepad that SDL opens through its
SInput driver, and has joypad-steam-input answer the same features command.
The driver is the 2.1.0 build.
Version 2.3.0 runs every profile on Windows on ARM64. HIDMaestro has two
drivers: the UMDF2 driver, which it self-signs on each machine, and the
USB/IP driver, the usbip-win2 host controller it carries. Windows on
ARM64 does not allow installing a driver self-signed on the machine, so
every controller there runs on the USB/IP driver, as a USB device that
Windows' own drivers bind, and a program needs no code change. On x64
the UMDF2 driver stays the default, and any profile can run on either
driver. The DLL builds and signs the UMDF2 driver's catalogs itself and
no longer carries Windows SDK or WDK tools. The UMDF2 driver is the
2.1.0 build.

Setup and validation
Device creation and driver installation require administrator rights.
For 2.3.0, the 111-scenario regression battery passed on three systems.
On a Lenovo Legion Pro 7 16AFR10H laptop (AMD Ryzen 9 9955HX3D, 64 GB
DDR5-5600, Windows 11 IoT Enterprise LTSC), all 111 scenarios passed.
On a MeLE PCG02 GLE stick PC (Intel Celeron J4125, 8 GB LPDDR4-2133,
Windows 10 IoT Enterprise LTSC), 107 scenarios passed and 4 skipped on
the UMDF2 driver and again with every controller on USB/IP, leaving out
the checks that need a Steam client, a desktop session or Windows
Sandbox. On a Microsoft Surface Pro for Business, 12-inch (2nd Edition)
(Qualcomm Snapdragon X2 Plus, 24 GB LPDDR5x-9523, Windows 11 Pro on
ARM64), where every controller runs on USB/IP, 107 passed and 4
skipped.

Performance
Each release's notes compare it with the release before it, both builds
measured in one session on the development laptop. Chained from those
comparisons, 2.1.0 takes 76% of 1.12.0's time from process start to the first
DualShock 4 controller, 43% of its time to create an Xbox 360 controller, 77%
of its time from SubmitState to a game's ReadFile on a DualShock 4, and 24% of
its time for a SubmitState call on an Xbox 360 pad. Every tracked path, slower
steps included: https://hidmaestro.org/performance.html

Adoption
PadForge is built on HIDMaestro end to end. Other public projects that use,
